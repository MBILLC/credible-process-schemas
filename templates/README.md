# Templates

Minimal records that conform at the named level — nothing more than the profile demands, every
resource a placeholder path under `resources/`. Copy one, rename the file, replace every
`resources/<Step>-<Particle>.md` with your real content (or a `stc:ResourceReference`), fill
`GeneralInformation` (GUID, name, version, author, description), and run `csp check`.

| File | Record | Level |
|---|---|---|
| `stmd-cl1..cl4-template.xml` | Credible Simulation Process (STMD) | CL1–CL4 |
| `dtmd-cl1..cl4-template.xml` | Credible Decision Process (DTMD) — carries `credibility.level` on `DefineResultQuality/Output` | CL1–CL4 |
| `mtmd-cl1..cl4-template.xml` | Credible Modeling Process (MTMD) — `model-validation.mode` on `GeneralInformation` from CL3 | CL1–CL4 |

Notes: the life-cycle entries carry an *empty* `ssc:Signature` element (the presence rule
STC-INT-100 passes; a real signature comes from `csp sign`). `Links` particles at CL4 hold the
placeholder locators `#self`/`#related`. The STMD/MTMD templates state the level on
`GeneralInformation`; in a package with a decision record, reference the DTMD from there instead
(`stc:ResourceReference xlink:href="DecisionTask.dtmd"`) and drop the local `credibility.level`.
Generated by `credible-process-tools/examples/make_templates.py`; regenerate after a matrix change.
